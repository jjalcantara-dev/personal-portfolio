# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## Commands

```bash
npm run dev            # Start dev server at localhost:3000
npm run build          # Production build (SSG)
npm run start          # Serve production build locally
npm run lint           # Run ESLint
npm run i18n:check     # es.json and en.json must have the same keys (exit 1 otherwise)
npm run puzzles        # Regenerate puzzle levels (slow; see scripts/puzzles/README.md)
npm run puzzles:verify # Every puzzle level: single solution, no repeated boards
npm run cv             # Build the public CV PDFs into public/
npm run cv:private     # Build CVs with phone number into cv/private/ (git-ignored)
```

No test suite is configured. CI (`.github/workflows/ci.yml`, Node 22) runs lint, `tsc --noEmit`, `i18n:check`, `puzzles:verify` and `build` on every push and pull request; keep all five green.

## Environment Variables

None. The site is fully static and has no backend services.

## Architecture

**Framework:** Next.js 16 App Router with full SSG. i18n routing is handled by `proxy.ts` (Next 16 proxy): paths without a locale redirect to the `preferred_locale` cookie if set, otherwise to the `Accept-Language` match, falling back to `es`. The cookie is written by `lib/locale-cookie.ts`.

**i18n:** Two locales (`es`, `en`), default is `es`. All routes live under `app/[locale]/`. Content is loaded from `content/es.json` / `content/en.json` via `lib/content.ts` → `getContent(locale)`. The `Content` type is inferred from `es.json` (source of truth for the type).

**Layout chain:** `app/layout.tsx` (bare html shell) → `app/[locale]/layout.tsx` (sets `<html lang>`, wraps with `Header`, `Footer`, `BottomNav`, `StructuredData`). There is no cookie banner: the only cookie is the technical language one, disclosed in a footer note and the privacy policy. Each page receives `params: Promise<{ locale: string }>` and should resolve and validate the locale with `isValidLocale()` from `lib/i18n.ts`.

**Daily Puzzles (`/puzzles`):** two kinds alternate day by day (00:00 UTC): "Desbloquea" (sliding blocks, `components/games/SlidePuzzle.tsx`) and "Puentes" (bridges between islands, `components/games/BridgesPuzzle.tsx`). `lib/games/selector.ts` walks each list in order from 2026-01-01, so nothing repeats for 120 days. Levels live in `lib/games/library.ts`, which is GENERATED by `npm run puzzles` (`scripts/puzzles/`, see its README): every level is checked by an exhaustive solver to have exactly one solution. Never edit levels by hand.

**Contact page:** Static list of email, LinkedIn, GitHub and location. There is no contact form and no API route; the privacy policy states the site collects no personal data, so keep it that way unless the policy is updated too.

**Social preview image:** `app/[locale]/opengraph-image.tsx` generates the 1200×630 Open Graph image per locale (`twitter-image.tsx` re-exports it). Pages that define their own `openGraph` metadata replace the layout's, so they must include `images: ogImages(locale)` from `lib/og.ts`.

**Intro (`components/Intro.tsx`):** ~1.8 s logo animation on every full page load (first visit, reload, new tab), never on client-side navigation between pages. Pure CSS (the `Intro on full page loads` block in `globals.css`); `INTRO_GATE` in `<head>` sets `<html data-intro>`; skipped for `prefers-reduced-motion`; click or any key opens it at once. It stores nothing on the device.

**Styling:** Tailwind CSS v4 with PostCSS. Global styles in `app/globals.css`. Inter font via `next/font/google`. `@source "../lib/**/*.ts"` is set in `globals.css` so Tailwind scans the constants files.

**Design system constants:**
- `lib/constants/colors.ts` — semantic color tokens (`clr`, `focusRing`, `btnPrimary`, `btnOutline`, `btnGhost`, `externalLink`, `skillTag`). Use these everywhere instead of hardcoded Tailwind color classes.
- `lib/constants/typography.ts` — semantic type scale (`tx`). Use these for all heading/body/label sizes.
- **Rule:** modifier-prefixed classes (e.g. `group-hover:text-gray-800`) must stay hardcoded in components — Tailwind cannot scan dynamic class strings.

**Mobile navigation (`components/BottomNav.tsx`):** Fixed bottom nav, visible only on mobile (`sm:hidden`). Features filled/solid icons for the active section, a persistent pill background on the active item, and labels always visible for all items. The `/collab` page is titled "Compañeros" / "Colleagues". Pages not in the bottom nav (`/puzzles`, `/privacy`, listed in `SECONDARY_PAGES` in `components/MobileBackButton.tsx`) get a floating back arrow top left, paired with the language toggle top right: it goes back if the visitor came from another page of the site, otherwise to home.

**CV (`cv/`):** LaTeX source of both CVs: `cv_en.tex`, `cv_es.tex` and the shared layout `cv-style.tex`. `npm run cv` compiles them with latexmk (needs a local TeX Live) and copies the PDFs into `public/`. Both must stay on one A4 page and in sync with the experience on the site; check the page count after every change. The repo is public, so keep private notes out of `.tex` comments. `npm run cv:private` builds a copy with the phone number into `cv/private/` from `cv/private.tex` (template: `cv/private.example.tex`); both paths are git-ignored and the public build never reads that file. Never commit the phone number.

**Adding content:** Edit `content/es.json` and `content/en.json` in parallel — both must stay in sync.

**Shared constants (`lib/site.ts`):** `SITE_URL`, `SITE_NAME`, `AUTHOR_NAME`, `CONTACT_EMAIL`, `SOCIAL_URLS`, `displayUrl()` and `isSafeUrl()`. Never hardcode the domain, email or profile URLs in pages or components.

**Page metadata (`lib/seo.ts`):** subpages build their metadata with `pageMetadata({ locale, path, title, socialTitle?, description, keywords?, type? })`, which sets canonical + hreflang and full Open Graph / Twitter with the generated image. JSON-LD: `components/StructuredData.tsx` emits `Person` and `WebSite` site-wide; `ProfilePage` only on `/about` (`profilePageJsonLd`).

**Projects (`components/ProjectCard.tsx`):** each card is a `<ProjectCard>` (image or text logo, optional badge, type, role, description, stack tags, external links with icons); the page only passes data.

**Adding a new page:** Create `app/[locale]/your-page/page.tsx`, call `getContent(locale)` for translations, and add nav entries in both JSON files and `components/Navigation.tsx`. Its `generateMetadata` must return `pageMetadata({ locale, path: "/your-page", ... })` (`lib/seo.ts`); without its own canonical the page inherits the home one and search engines treat it as a duplicate of home. Add it to `app/sitemap.ts` too.
